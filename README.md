# go_routine_bot

Учебный проект на Go.

## Назначение

Telegram-бот для учеников языка Go и менторов. Помогает ученику работать с планом обучения, отправлять решения на проверку и обращаться за помощью к ментору.

## Подход к первой версии

- Выбираем простые решения, достаточные для функциональных требований и обеспечивающие достаточную безопасность.
- Необходимость каждого требования для первой версии можно обсуждать и оспаривать.
- Собственную платформу уровня LeetCode и полноценную онлайн-школу в первой версии не строим.
- В первой версии у бота две роли: ученик и ментор. Ментор сам принимает административные решения в боте. Внешняя поддержка и администраторы остаются доступны ученикам вне бота.

## Требования

Описаны регистрация и возможности ученика и ментора. Уточняем результаты действий и изменения состояния в [таблице кейсов](CASES.md).

### Регистрация и доступ

- Список менторов задаётся через переменные окружения как коллекция числовых ID пользователей Telegram. Бот сверяет ID отправителя, полученный от Telegram, с этим списком. Пользователь из списка получает доступ ментора без приглашения. Ментор может отключать и снова включать бота для себя, пока его ID есть в списке. В одном экземпляре бота ментор не может быть учеником.
- Бот можно запустить с пустым или незаданным списком менторов. В этом случае на каждое обращение, включая обращение ранее зарегистрированного ученика, бот отвечает: «Пользователь с id {id} не зарегистрирован, обратитесь к владельцу бота». Вместо `{id}` бот подставляет числовой Telegram ID отправителя. Так пользователь может узнать свой Telegram ID.
- Новый ученик регистрируется через инвайт-ссылку с определённым идентификатором. Если новый ученик обращается без приглашения, бот сообщает об ошибке доступа.
- В первой версии приглашение одноразовое: после успешной регистрации одного пользователя ссылка больше не работает для регистрации.
- Временные приглашения оставлены на будущее; в первой версии их не предусматриваем.
- Ментор может создать сколько угодно разных одноразовых ссылок и выдаёт каждому ученику отдельную. Если два новых пользователя одновременно открыли одну ссылку, зарегистрироваться по ней может только один. Обращение уже активного ученика сохраняет действующую ссылку для регистрации другого пользователя.
- Ученик может самостоятельно отключиться от бота. Доступ к функциям бота прекращается. Для повторного подключения нужна новая одноразовая ссылка-приглашение. При отключении весь учебный прогресс сбрасывается. По новой ссылке обучение начинается заново у прежнего или у другого ментора.

### План обучения и навигация ученика

- Ученик работает с планом обучения, состоящим из тем.
- У темы могут быть практические задачи и тест. Тест может отсутствовать.
- Для ученика сохраняется указатель на текущую задачу в рамках темы.
- Ученик может выбирать следующую или предыдущую задачу.
- При возврате к предыдущей теме она становится текущей. Если в теме есть задачи в статусе «НЕ РЕШЕНА», указатель переходит к первой из них.
- При обращении к боту ученик может запросить текущую задачу, список задач текущей темы со статусами и перейти к другой доступной теме. Если в теме есть практика, но ни одна задача не имеет статуса «НЕ РЕШЕНА», кнопка открытия текущей задачи отсутствует.

### Практические задачи

| Статус | Индикатор | Значение |
| --- | --- | --- |
| НЕ РЕШЕНА | Красный | Задача ещё не решена |
| НА ТЕСТИРОВАНИИ | Оранжевый | Выполняются автоматизированные проверки отправленного решения |
| НА ПРОВЕРКЕ | Жёлтый | Автоматизированные проверки пройдены, решение ожидает проверки ментором |
| РЕШЕНА | Зелёный | Ментор принял решение ученика |

- Для сдачи ученик прикрепляет к сообщению файл с расширением `.go`.
- Отправить решение, в том числе повторно, можно только для задачи в статусе НЕ РЕШЕНА. При отправке задача переходит в НА ТЕСТИРОВАНИИ, начинаются автоматизированные проверки.
- Решение проходит автопроверку, если оно собирается, запускается и выдаёт ожидаемый для задачи результат за отведённое время. После технического сбоя автопроверки ученик отправляет решение повторно.
- Успешное прохождение автоматизированных проверок переводит задачу в НА ПРОВЕРКЕ и добавляет её в список работ для проверки ментором.
- При провале автоматизированных проверок или отказе ментора задача переходит в НЕ РЕШЕНА; ученику отправляется сообщение. При отказе ментора сообщение содержит его комментарии.

### Тест по теме

- Ученик проходит тест целиком.
- В первой версии у каждого вопроса четыре варианта ответа, из которых один правильный. Ученик может выбрать только один вариант на вопрос.
- После завершения теста ученик видит процент правильных ответов и по каким вопросам он ответил правильно или ошибся.
- Тест пройден, если процент правильных ответов выше или равен порогу. В первой версии порог равен 100%. Результат пройденного теста сохраняется, отозвать его нельзя. В прогрессе ученика хранится лучший процент среди завершённых попыток.
- Возможность настройки критерия прохождения ментором оставлена на будущее.
- Пока попытка активна, бот сохраняет текущий вопрос без ограничения по времени. После перерыва ученик продолжает с этого вопроса. Явный выход из теста прерывает попытку. Следующую попытку ученик начинает с первого вопроса.

### Доступ к следующей теме

- Для открытия новой темы проверяются статусы задач всех предыдущих тем: все они должны быть НА ПРОВЕРКЕ или РЕШЕНА.
- Последняя доступная тема — самая дальняя по порядку плана из уже открытых ученику. Чтобы открыть следующую за ней тему, ученик должен пройти тест последней доступной темы, если в ней есть тест. Это правило действует и при возврате к более ранней теме.
- Если последняя доступная тема содержит только теорию, ученик должен получить ссылку на её материал. Следующая тема открывается автоматически, как только выполнены все условия. Выбранная учеником тема при этом остаётся текущей.
- Уже открытая тема остаётся доступной, даже если ментор позднее отклонит работу из предыдущей темы. Отклонённая работа блокирует открытие новых тем, пока снова не достигнет статуса НА ПРОВЕРКЕ или РЕШЕНА.

### Помощь ментора

- Ученик с активным доступом может запросить помощь ментора.
- Для первой версии предлагается отправлять пинг сразу. Лимит составляет один пинг в час на каждого ученика. Ментор самостоятельно связывается с учеником.

### Возможности ментора

- Ментор может открыть список всех зарегистрированных у него учеников и выбрать ученика, чтобы посмотреть его сведения и прогресс.
- Ментор также может запросить прогресс своего ученика напрямую по никнейму. Ментору доступны сведения и работы только его учеников. Поиск по никнейму чужого ученика даёт тот же ответ, что и поиск по неизвестному никнейму.
- В отчёте тема считается пройденной, когда все её практические задачи имеют статус «НА ПРОВЕРКЕ» или «РЕШЕНА», а лучший результат теста достиг порога. Каждое условие применяется, если в теме есть соответствующие задания. Для тем с тестом в отчёте указывается лучший результат.
- Ментор может создать одноразовую ссылку-приглашение для нового ученика. После регистрации по ссылке ученик появляется в списке этого ментора.
- Ментор может удалить своего ученика. Весь учебный прогресс сбрасывается, доступ прекращается. При повторном подключении по новой ссылке обучение начинается заново. Ученик получает информационное сообщение с предложением обратиться за внешней поддержкой. Перенос прогресса отложен до следующей версии.
- Ментор сам выбирает, сколько сводок получать в день, и задаёт время каждой. В выбранное время бот собирает для сводки все задания его учеников, которые находятся в статусе НА ПРОВЕРКЕ.
- Из списка работ ментор может открыть задачу и посмотреть текст решения ученика, принять работу или отклонить её.
- При принятии задачи комментарий необязателен, а задача переходит в РЕШЕНА. При отклонении комментарий обязателен, а задача переходит в НЕ РЕШЕНА, и бот отправляет ученику комментарий.

### Открытые вопросы и границы первой версии

- Как возвращается к работе уже зарегистрированный ученик с активным доступом?
- Нужно ли ментору по-прежнему указывать причину удаления ученика и где её хранить?
- Достаточно ли одного заранее подготовленного плана для всех учеников?
- Какие ограничения безопасности и ресурсов должны соблюдаться при сборке и запуске чужого кода?
- Можно ли повторно пройти уже зачтённый тест?
- Что видит ученик при повторном запросе помощи до истечения часа?
- Что именно входит в сведения об ученике и его прогрессе?

Решения по этим вопросам предстоит принять по мере проработки соответствующих сценариев.
